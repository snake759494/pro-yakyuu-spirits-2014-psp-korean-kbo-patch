# KBO 구단별 외형·연고지 패치 규칙

사용자 요청(2026-10-11): 한화 작업을 참고하여 LG와 이후 구단에 같은 점검 절차를 적용한다. 팀 이름 하나나 대표 로고 하나만 바꾸고 완료 처리하지 않는다.

ID와 파일의 숫자는 0부터 시작한다. 1을 빼지 않는다. 텍스트 약칭은 `kbo_names.json`의 고정 위치 및 문자열을, 비트맵 약칭은 `TEAM*_H/V.CHK`의 `UP04T`를 각각 바꾼다. 일반 짧은 팀명과 한 글자 약칭은 다른 필드이다.

## 필수 점검 경로

1. 구단 정식명·짧은 이름·한 글자 약칭·영문명·연고지의 원문과 고정 필드 위치를 확인한다. 컨텍스트 없는 바이너리 일괄 치환은 하지 않는다.
2. 로고는 `MENU2D`, `SELECT`, `TMFLAG`, `RK_FPLAY`, `PET_*1/2`, `TEAM*_H/V`의 `UP05T` 및 응원 깃발 `TEXH/PALH`, `SOLHBG*`와 경기장·유니폼·메뉴 모자를 따로 조사한다. 선수 얼굴 및 메뉴 로고가 쓰는 번호 체계도 구분한다. 공식 BI 이미지의 테두리를 제거하고 투명 여백을 잘라 실제 표장 크기로 맞춘다.
3. 유니폼은 `Nxx*_H1/H2/V1`의 D/N/E, `AS_`, `CT_`, `TMSEL` 및 `TMSELUNI*`를 포함한다. 원정과 홈은 별도 디자인이며 단색 덮기만으로 완료하지 않는다. 상의 UV의 앞면이 양 끝으로 분할되는지 확인한다.
4. 모자·헬멧·소매·상의·하의·메뉴 미리보기와 등 이름/번호 아틀라스를 구분한다. 글자 아틀라스에 로고를 덧씌우지 않는다. 선수 등의 문자열은 PDN 92:104, 등번호는 확인된 비트 필드로 기록한다. LG 상의의 단추 여밈은 회전한 256픽셀 UV의 x=11/245를 기준으로 좌우 로고를 나눈다. 파일 가장자리 0/256으로 나누면 글자가 잘린다.
5. 실제 홈구장과 유사한 원본 모델을 고른다. 개방/돔, 좌우 대칭, 관중석 형태, 잔디, 치수를 비교하고 선택 이유와 차이를 문서화한다. 구장 이름만 바꾸지 않는다.
6. 홈 슬롯/일정, 리소스 이름, 낮·밤 모델, 충돌, 조명, 카메라, 치수, 선택 미리보기를 함께 맞춘다. 광고판은 SINF/PGOX UV 연결을 읽고 각 조각 안에 글자를 맞춰 잘림을 막는다. 모델과 물리 치수를 거짓으로 다르게 쓰지 않는다.
7. 파일 크기·팔레트·나머지 픽셀 및 비대상 구장 보존을 검사하고 최종 ISO를 재읽기한다. 사용자 SYSTEM.DAT 복사본으로 새 페넌트와 실제 경기 화면을 확인한다. 이전 상태저장으로 새 ISO 검증을 대신하지 않는다.
8. 결과 스크린샷을 최종 ISO SHA-256과 연결하고 관찰한 화면만 검증 완료로 기록한다. 확인 후 PPSSPP를 종료한다. 설치 데이터는 기본 빌드에서 생성하지 않는다.

## LG 적용 근거와 한계

서울·잠실 명칭, 공식 BI와 2026 홈/원정 디자인을 참고한다. LG 공식 자료: [BI](https://www.lgtwins.com/twins/about/bi), [잠실 홈구장](https://www.lgtwins.com/twins/about/homeGround?ground=seoul), [2026 유니폼](https://twinslockerdium.co.kr/product/list.html?cate_no=236).

LG 홈구장 표와 일정은 CHIBA 슬롯7로 지정한다. 슬롯7의 낮·밤 선택 미리보기를 그대로 함께 사용한다. 낮·밤 리소스와 원 모델 충돌/치수(좌우99.5m, 중앙122m)를 함께 유지한다. 실제 잠실(좌우100m, 중앙125m)과 동일한 신규 3D 모델은 아니다. 본문의 간판 교체는 광고판 UV 단위이며 모든 관중·도시 배경의 한글화를 의미하지 않는다.

홈은 흰색 핀스트라이프, 원정은 검정 상의, 보조 유니폼은 회색 계열로 구성한다. 원본 모델의 재단/형상은 유지한다. 등 영문명과 번호는 이전 LG 선수 패치를 이어 사용한다.

현재 빌드와 실행 검증 상태는 `build/runtime_validation.json`을 기준으로 판단한다.
