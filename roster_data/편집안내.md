# KBO 선수 데이터 인계

GUI에서 619명 선수, 50명 스태프, 얼굴/능력치/구단/유니폼/구장 값을 수정하려면 [KBO 편집기 안내](../KBO_편집기_안내.md)를 참고해 `KBO_편집기_시작.bat`을 실행한다. Codex 입력 패키지는 `editor_data/exports/KBO_editor_input_latest.zip`으로 저장된다. 아래는 기존 빌드 입력 구조를 직접 편집할 때의 안내다.

`KBO_2026_전체선수_스태프.json`은 현재 빌드 입력을 한곳에 모은 UTF-8 통합 보관본이다. 선수 619명(1군 290명, 2군 329명), 스태프 50명을 포함한다. 선수별 신상 원본, 적용 능력치, 구종, 자료 출처, 추정 항목과 1·2군 구분을 보존한다.

## 실제 수정할 파일

- 기본 능력치·구종·주 포지션·개막 1군 명단: `translation/kbo_2026/ratings_review.json`
- 선수 등록명·신상·스태프: `translation/kbo_2026/LG.json` 등 구단별 JSON. 한화는 `translation/hanwha_2026.json`이다.
- 전 선수 사진·얼굴 자원·키·체형·피부색 연결: `translation/kbo_2026/appearance.json`. `player_id`, `index`, 사진 출처와 해시를 함께 검토한다. 통합 보관본의 `applied_appearance_record`에도 수록한다.
- 선발 타순·수비 배치·선발 로테이션·마무리: `tools/kbo_team_layout.py`의 `STARTERS`, `ROTATIONS`, `CLOSERS`. 현재 이 부분은 JSON이 아닌 코드에 있다.

통합 보관본만 편집해도 게임에 자동 적용되지는 않는다. 각 팀의 `identity_source`, `ratings_source`가 실제 입력 경로를 안내한다. 수정 후 통합 보관본을 다시 내보낸다. `source_files`는 내보낼 때의 입력 파일 해시다.

신상 원본의 과거 `opening_entry`와 최신 편성이 다를 수 있다. 통합 파일의 `squad`는 실제 편성에 쓰는 `ratings_review.json`의 `opening_indices`를 기준으로 한다. 이름이 같은 선수는 `player_id`(KBO 선수 ID)로 구별하고, `index`(게임 레코드 위치)와 혼동하지 않는다.

## 필드 설명

|키|의미|
|---|---|
|category|투수는 P. 야수 분류는 기존 선수의 형식을 따른다.|
|primary_position|0 투수, 1 포수, 2 1루, 3 2루, 4 3루, 5 유격, 6 좌익, 7 중견, 8 우익|
|trajectory|탄도|
|contact_r / contact_l|우투수 / 좌투수 상대 컨택|
|power / speed|파워 / 주력|
|arm / catching / throwing|어깨 / 포구 / 송구|
|recovery / stamina|회복 / 투수 스태미나|
|starter / reliever / closer|선발 / 중계 / 마무리 적성|
|fielding|포지션별 수비 능력. P, C, 1B, 2B, 3B, SS, LF, CF, RF|
|velocity|구속 km/h|
|pitches|구종 배열: name 이름, break 변화량, stuff 구위, control 제구|
|usage_pct|자료상 구사율. 게임 능력 필드 자체는 아니다.|
|sources / estimated_fields|근거 자료 / 미확인·추정 사항|

탄도·투수 적성·변화량·구위·제구는 저장 범위 0~7, 주요 기본 능력치·수비는 저장 범위 0~127이다. 이는 비트 저장 한계이지 권장 평가 범위가 아니다. 기존 환산 기준과 `translation/kbo_2026/RATINGS_REVIEW_RULES.md`를 따른다. 지원 구종은 `tools/player_fields.py`의 `PITCHES`에 정의되어 있다. 같은 방향 구종은 최대 두 개다.

선수 교체나 보직 변경 시 능력치와 신상 양쪽을 맞춘다. 개막 편성은 구단마다 29명이며 `opening_indices`, `opening_player_ids`, 선수별 `opening_entry`를 함께 맞춘다. 선발 타순과 마무리도 반드시 1군에 포함되어야 한다. 슬롯 추가·삭제·이적은 단순 이름 변경으로 처리하지 말고 팀 편성과 슬롯 매핑을 재검증한다. 현재 검증기는 전체 619명 구조를 전제로 한다. 게임 ID·음성 키·레코드 크기를 임의 변경하지 않는다.

`tools/prepare_ratings_review.py`는 능력치 JSON을 재생성하므로 수동 편집 후 무심코 실행하면 수정 내용을 덮어쓴다. 자료가 부족한 선수의 추정 표시를 확인 없이 지우지 않는다. 외형·등이름·이름 글꼴 등은 별도 리소스 작업도 필요할 수 있다.

## 검증과 빌드

작업 폴더에서 실행한다.

```powershell
python -X utf8 tools/test_ratings_review.py
python -X utf8 tools/build.py --league-trial --check
python -X utf8 tools/build.py --league-trial
python -X utf8 tools/test_kbo_roster_runtime_fields.py
python -X utf8 tools/export_roster_handoff.py
```

설치 데이터는 기본적으로 생성하지 않는다. 새 ISO 해시를 기록하고 독립 메모리 스틱으로 새 페넌트를 시작하여 보직·1군 편성·능력치를 확인한다. 기존 상태저장으로 검증하지 않는다. 사용 후 PPSSPP를 종료한다. 기존 페넌트 저장 데이터가 자동으로 갱신된다고 가정하지 않는다.

이 보관본은 이번 요청에서 새로 평가한 데이터가 아니라 현재 패치 입력의 보존본이다. 투수 38명의 구종 추정, 일부 능력치 추정, 통산 기록에 원 일본 경력이 남는 제한은 `ROSTER_RATINGS_REVIEW.md`를 참고한다.
