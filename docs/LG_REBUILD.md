# LG 트윈스 로스터 재작성

이전 LG 매핑·타순·생성 능력치 JSON을 입력으로 쓰지 않고, 원본 게임 레코드와 새로 받은 KBO 공식 명단에서 다시 작성했다. 이번 범위는 LG이며, 다른 9개 팀의 옛 저장 편성은 그대로 남아 있다.

## 반복 오류 원인

ISO 선수 데이터의 주 포지션과 기본 편성을 바꿔도 SYSTEM.DAT에 저장된 이전 팀 편성이 새 페넌트에 다시 적용됐다. 이전 검증은 빈 시스템 저장 환경으로만 진행해 이 문제를 놓쳤다. 사용자가 남긴 SYSTEM.DAT 복사본으로 기존 현상을 재현했다. 증거: `build/lg_rebuild/01_reproduced_with_user_system.png` (이전 b717ca4a 빌드).

새 팀 편성 화면 생성자에서 원본 게임의 단일 팀 초기화 함수를 호출해 LG만 새 ISO 명단으로 구성한다. 진행 중인 기존 페넌트 저장을 변환하는 수정은 아니다. 새 팀 편성 화면에 다시 들어오면 LG 사용자 지정 편성도 기본 명단으로 초기화되는 점에 유의한다. 다른 팀의 저장 편성을 지우지 않으며, 사용자 외부 저장 파일은 직접 수정하지 않는다.

팀 편성 미리보기에는 비DH 상수가 따로 있었다. 이를 DH로 바꾸어 문보경이 벤치로 밀려나는 표시도 수정했다. 실제 시즌 DH 코드는 유지한다.

원본 LG 투수 슬롯만으로 36명을 채울 수 없어 부족분은 다른 KBO 팀이 사용하지 않는 원본 투수 슬롯에서 가져왔다. 야수 레코드를 이름과 포지션만 투수로 바꾸는 방식을 배제하여 구종·구속·스태미나가 없는 예비 투수가 생기지 않게 했다. 사용한 원본 레코드의 능력값과 ID는 그대로 보존하며, 사용하지 않게 된 LG 야수 슬롯은 자유선수 풀로 보낸다.

## 명단과 배치

- 선수 63명: 투수 36, 포수 4, 내야수 12, 외야수 11.
- 게임의 1군 28명 한도: 투수 13, 야수 15.
- 선발: 치리노스, 톨허스트, 임찬규, 웰스, 이정용.
- 중계: 함덕주, 우강훈, 이우찬, 배재준, 김영우.
- 셋업: 김진성, 장현식. 마무리: 유영찬.
- 타선: 홍창기(RF), 신민재(2B), 오스틴(1B), 문보경(DH), 박동원(C), 문성주(LF), 오지환(SS), 구본혁(3B), 박해민(CF).
- 야수 벤치: 이주헌, 이영빈, 천성호, 최원영, 이재원, 송찬의.
- 외국인 4명 모두 1군: 치리노스, 톨허스트, 웰스, 오스틴. 투수 3명과 타자 1명으로 구분하고 외국인 판정 비트도 각각 기록한다.
- 감독 염경엽, 투수코치 김광삼, 타격코치 모창민, 수비코치 김일경, 주루/외야수비코치 송지만. 게임의 감독 1명·코치 4명 슬롯에 맞췄다.

실제 개막 등록은 29명이고 웰스는 당일 등록 명단 밖이었다. 외국인을 모두 1군에 두라는 사용자 요청과 게임의 28명 한도에 맞춰 웰스를 포함하고 박시원·백승현은 2군에 배치했다. 따라서 등록 인원은 실제 개막일 그대로라고 주장하지 않는다. 타자 김현수는 2026년 KT 소속이므로 LG에 넣지 않았다.

## 재현과 검증

`python -X utf8 tools/prepare_lg_fresh.py`로 명단을 재생성하고 `python -X utf8 tools/build.py --league-trial`로 빌드한다. 설치 데이터는 생성하지 않는다. `tools/verify.py`, `test_kbo_roster*.py`, `test_lg_fresh.py`로 ISO 읽기 검증, 원본 MIPS 등록명 함수, 보직, 생성자 초기화 보존을 검사한다.

사용자 SYSTEM.DAT를 독립 PPSSPP 메모리 스틱에 복사한 뒤 콜드 부팅하여 새 페넌트로 진입한다. 전체 팀 초기화 버튼이나 상태저장을 사용하지 않는다. `tools/audit_live_lg.py`는 실제 LG 63명/스태프 5명의 RAM 포인터, 전체 이름, 주 포지션, 저장 편성의 포지션 캐시, 외국인 비트, 1군 등록을 읽기 전용으로 검사한다. 최종 해시·실행 범위·스크린샷 해시는 `build/runtime_validation.json`에 기록한다.

## 남은 범위

후속 능력·외형 작업은 `LG_DETAILS.md`와 최신 `build/runtime_validation.json`을 기준으로 판단한다. 이전 명단 수정 빌드의 스크린샷은 이전 해시에만 해당한다. 시즌 완주와 기존 페넌트 저장 변환은 검증하지 않았다.
