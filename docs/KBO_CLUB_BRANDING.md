# KBO 추가 8개 구단 외형 작업

기존 한화·LG 승인 빌드에서 구단 외형·연고지·홈구장을 확장한다. 선수 개별 얼굴/체격/능력/등 영문명 재제작은 이번 작업 범위와 구분한다.

## 자원과 근거

`translation/club_brand.json`은 구단별 색상, 공식 BI 출처, 홈 슬롯, 간판 UV, 복제 자원 대응표다. `translation/club_brand_sources.json`에는 사용 표장 이미지의 SHA-256을 기록했다.

|삼성|대구|대구삼성라이온즈파크|YOKOHAMA 개방형|
|KIA|광주|광주기아챔피언스필드|HIROSHIMA 개방형|

3D 구장의 실제 KBO 형태/치수와 동일하다는 뜻은 아니다. 모델 형상·충돌·원 모델 물리 치수를 함께 유지하고 구단 표장을 교체한다. 선택 사진도 해당 원본 모델의 사진이다.

구단·홈구장 표장과 주요 간판을 대상으로 한다. 모든 일본 광고·도시 배경·음성까지 바꾸지 않았으며, 일부 바지/양말 무늬와 선수별 등 영문명은 원본 기반으로 남는다. 선수별 외형과 등 이름 재제작 완료로 해석하지 않는다.

두산/NC 복제는 사용하지 않는 원 도쿄/삿포로 파일 공간을 함께 재활용한다. 이에 따라 KBO 홈 10개 이외 일본 구장 선택 슬롯의 독립성은 보장하지 않는다. SSG 야간 보조 모델에는 원본 밤 조명 LIGHTS를 옮긴다. 크기 제약으로 밤 전용 조명 번짐 텍스처는 제외한다. 이 제한은 최종 검증에서 별도 기록한다.

## 재발 방지

- 0 기반 ID와 구단 자원 접두사를 직접 대조한다.
- 새 페넌트 생성 때 구단 배열 간격 0x28e8을 반영해 각 대상 팀을 별도로 초기화한다. LG를 다른 팀으로 덮어쓰지 않는다.
- 사용자 SYSTEM.DAT 원본은 바꾸지 않는다. 기존 진행 중 페넌트 저장의 명단을 자동 변환하지 않는다.
- 대전 모드에서 기존 저장 편성을 선택하면 이전 편성이 나올 수 있다. 이번 검증에서는 R을 누른 채 팀을 확정하는 게임의 초기 멤버 기능으로 ISO 명단을 사용한다.
- 대전의 DH 기본값은 COM 팀의 원 리그 슬롯에 영향을 받는다. 새 페넌트 DH 고정과는 별개이다. 경기 외형 검증 중 SSG/롯데 상호 대전은 비DH로 진행했으며, 이를 페넌트 보직 오류로 분류하지 않는다.
- 팔 긴소매(텍스처 3/5)와 바지·양말·신발(7/8/9)을 구별한다.
- 이름/번호 글자 아틀라스(18/20)는 색만 변경하고 글자 구조를 보존한다.
- 유니폼 선택 그림은 구단별 3~6개가 존재한다. 경기 자원의 H/V/C 변형을 모두 처리한다.
- 원 일본 유니폼의 줄무늬/목 뒤 표장을 남기지 않도록 같은 재단의 무지 원단을 사용한다.
- 한화·LG 승인 자원 50개를 `build/ss_brand/approved_resource_hashes.json`과 비교한다.

## 검증

`python -X utf8 tools/build.py --league-trial`

`python -X utf8 tools/verify.py`

`python -X utf8 tools/verify_club_brand.py`

독립 PPSSPP에서 새 페넌트 팀 편성을 연 뒤:

`python -X utf8 tools/audit_live_kbo_rosters.py SS HT WO KT LT OB SK NC LG`

보고서의 `passed`는 저장된 패치 명단과 실제 메모리 연결의 일치를 뜻한다. 모든 선수의 2026 공식 외형·등 영문명·능력치가 새로 검수됐다는 뜻이 아니다. 실제 화면의 완료 범위는 `build/runtime_validation.json`을 따른다.

## 전광판 로고 추가 점검

구장 M 파일의 T_TMMK1/2는 단일 구단 로고가 아니라 25×16 셀에 구단 ID 0~9가 두 번(셀 0~9 및 14~23) 반복되는 아틀라스다. 마지막 청크 T_TMMK2도 반드시 처리한다. 배열 외 픽셀은 보존하고 두 팔레트 형식(16/256색)을 각각 유지한다.

고정 길이 구장명 칸은 삼성=라이온즈파크, SSG=랜더스필드로 표시한다. 지나친 글자 축소를 피하기 위한 공식 명칭의 줄임말이며, 경기장 간판에는 지역을 포함한 전체 명칭을 사용한다.
