# 피부색·간판·스윙 판정·로고·등록명 수정

## 수정 내용

- 페라자: 원 일본 선수의 밝은 피부 설정을 중간 갈색 설정으로 변경했다. 강백호: 원 슬롯의 앤드루 존스용 어두운 설정을 동양인 피부 설정으로 변경했다. 얼굴·초상화도 같은 피부 기준으로 보정해 몸과 연결한다. 두 선수의 PLAYERDATA 152번 워드에서 피부 3비트만 변경하며, 기존 능력·ID·음성·등번호는 보존한다.
- 대전 간판: SINF의 재질 연결과 PGOX의 삼각형 스트립에서 실제 UV 패널을 추출했다. 낮/밤 33개 광고 텍스처를 각 패널 안에서 재배치하고 여백을 두었다. 긴 명칭은 충분히 넓은 패널에 쓰고 작은 패널은 ‘대전 볼파크’, ‘한화 이글스’를 사용한다. 건물 벽 전체를 광고로 덮지 않도록 외벽 영역을 보존한다.
- 스윙 판정: GAME2D의 TEX48에 있던 서로 겹치는 번역 영역을 원본 TCP60의 스프라이트 UV에 맞췄다. ‘빠름!’, ‘느림!’, ‘약간’, ‘타이밍’이 각자의 영역에 들어간다. 투구·스윙 속도나 판정 자체는 변경하지 않는다.
- 한화 로고: 경기 소개·점수 표시에서 사용하는 TEAME/TEAMEL 홈·원정 UP05T, 히어로 화면 SOLHBGE, RK_FPLAY의 별도 아이콘을 교체했다. 한화 경기 점수판 약칭은 ‘한’으로 변경한다. 메뉴와 경기 화면이 서로 다른 텍스처를 사용하는 것이 누락 원인이었다. GPU 프레임 기록의 실제 텍스처 바이트를 원본 아카이브와 대조했다.
- 채은성: 등록명이 두 번째 문자열을 선택하더라도 그 문자열이 비어 있으면 전체 이름을 반환한다. 짧은 등록명과 전체 등록명 경로를 모두 처리한다. 성과 이름을 합치는 다른 경로에는 개입하지 않아 중복 표시를 막는다. 기존 시스템 저장의 이름 선택 설정에도 대응하며, 이름 레코드 크기와 ID는 그대로다.

## 검증과 사용

최종 ISO 해시와 실제 관찰한 화면은 `build/runtime_validation.json`, 정적 검사는 `build/validation.json`에 기록한다. `tools/test_visual_fixes.py`는 원본 MIPS 표시 함수를 실행해 빈 등록명과 일반 이름을 검사하며, 모든 실행 파일의 직접 호출자를 대조해 이름 처리 범위를 검증한다.

회귀 검사 26개와 ISO 재읽기·정적 검사를 통과했다. PPSSPP 직접 타격에서 ‘빠름!’ 판정, 페라자·강백호 피부색, 채은성 타석 이름을 확인했다. 이후 로고 4개 파일의 크기만 최종 보정했고, 나머지 빌드 영역의 일치를 검사했다. 최종 ISO를 새로 부팅하여 타순·타석·주자·경기 요약·종료 점수표·히어로·승리 화면의 한화 로고를 확인했다. 1이닝 관전 경기는 게임 내 요약 진행으로 4:0 종료했다. 이는 9이닝 사용자 조작 경기 완주 검증이 아니다. 검증 후 PPSSPP는 종료했다.

‘느림!’과 ‘약간’은 UV 및 생성 텍스처로 검사했으며 이번 직접 타격에서 모든 판정 조합을 발생시키지는 못했다. 기존 저장의 등록명 선택값은 MIPS 함수 검사로 확인했으며 사용자 페넌트 저장을 직접 재로드한 검증과 구분한다. 최종 보정 전·후 화면은 서로 다른 ISO 해시로 기록한다.

게임을 완전히 종료한 뒤 Korean DEV ISO를 새로 부팅한다. 상태 저장은 예전 코드와 텍스처를 유지할 수 있다. 이번 빌드도 설치 데이터는 재생성하지 않았다. 오래된 시스템/페넌트 저장은 예전 피부·선수 설정을 포함할 수 있으므로 새 환경에서의 실행 결과와 구분해야 한다. 사용자 저장은 삭제하지 않는다.

기존 얼굴형과 64×64 텍스처의 한계, 대전 구장의 근사 모델, 다른 팀의 일본 선수·유니폼, 일본어 음성, 포스트시즌 등 이전 미완성 범위는 그대로다. 모든 선수·각도·경기 연출을 전수 확인했다는 의미는 아니다.
